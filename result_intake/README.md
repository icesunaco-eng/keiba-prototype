# 既存結果の入力ステージ

既存の正規化レコードを、原資料の出典を保った中間入力へ接続する。予測入力への自動昇格はしない。`stage(record, meta)` を呼ぶ。全てメモリ内、原本・正規化資料への書込みなし。追加取得・通信・投票なし。

レース内キーは日付/場/回/日/競走/馬番で構成。これは同じ馬をレース間で追うIDではない。馬名一致を同一馬と推定せずhorse_id=None。行順着順はfinish_candidateとして残し、確定着順に勝手に昇格しない。scheduled_post_labelとactual_startを分離し、HTTP更新時刻から発表日時を捏造しない。確定オッズ・払戻は返却しない。source_hashは入力メタデータの記録値であり、この部品がPDFバイトを照合したという意味ではない。

## 既存実資料との接続
参照 https://app.notion.com/p/419f1dff94dc8189b432f1b246e6a233 の既存正規化JSONおよびsource-metaを許可済み接続から読取り。正規化JSONの14行をステージへ接続できた。history_rows=0、model_ready=False、announced_at=nullを確認。正規化入力のcanonical JSON SHA256: d8c05902001d33b7053ce7d8aeada2caf7d931773ac581084ac925a710a9ad79。

実資料・馬名一覧・金額・原本をこのrepositoryへ保存しない。実レコードの結果は上記件数と限界のみ記録。実資料の新規取得なし。原PDFの再抽出・目視照合・原資料hashの再計算は今回していない。

## 残る接続作業
安定馬IDを根拠で対応させること、履歴利用可能時刻の根拠、行順着順候補の採用根拠が不足。実発走時刻は原資料から未確認で、予定表示と区別して残す（将来の全特徴に実発走秒が必須と決めたわけではない）。今回のstagingは既存strict history APIへまだ直接渡さない。確定結果を当該レースの発走前予測へ流さず、将来対象の過去走利用とも分ける。

同着の追加分析なし。モデル学習・確率較正・実予測・本番完成ではない。保持した候補を正式成績や注文に使わない。

## 独立確認と入力hash訂正
作者4件・独立再現4件＋追加5境界成功。独立担当が既存Mac正本で14行接続、履歴0、model/prediction/order false、元ファイルバイト不変を確認。raw正規化ファイルSHA256は f4e2ca9c0be1666ee730bc1a2d62dc9541737b7f4a7a84333c77afe0e4644e5d。初回の中継でJSONの7.0を7へ変換しcanonical hashが変化したため、そのhashは不採用。JSON本文を文字列のままPythonへ渡し、正本と同じd8c059…を作者側でも再現。数値型/表現を勝手に丸めない。非dict行がAttributeErrorになる小改善余地は残るが、その際も予測入力は生成しない。実資料の真偽・発表時刻・着順昇格は未検証。
