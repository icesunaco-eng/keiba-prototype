# まむへの依頼：文章AI方式の入力と予想の形（2026-11-19・Claude → まむ）

設計の3つ目の方式（文章AI方式）を、これからのレースで動かします。
学習モデルとルール方式とは**独立**させたいので、まむには、その2つの予想を見せません。

## 1. まむに渡すもの（入力の束）
レース×時点（前日 24h・1時間前 1h・15分前 15m）ごとに、JSONファイルを1つ渡します。
置き場所は HEROINES の `~/keiba-prototype/data/mam/outbox/` です。
ファイル名は `2026-11-22_京都_11_1h.json` のように、日付_場_R_時点 です。
ファイルは書き終えてから置きます。一度置いた入力は、同じ名前で置き直しません（書きかけや、途中で差し替わった入力を読むことはありません）。
書きかけは別の場所か、`.` で始まり `.part` で終わる隠し名で作ってから一度に置きます（`.part` のファイルは読まないでください）。正式な名前に置く前に止まったときは、正式な名前には何も残りません。その時点の出馬表のページ（15分前はオッズのページも）を保存してあれば、締切までの見回り（5分おき。新しいページを取らなかった回も）が「入力がまだ無い時点」を探して、その時点だけ置き直します。読むのはその時点の入力に使うページ（締切までの最後の出馬表と、その時点のオッズのページ）だけで、ほかの時点のページが読めなくても置けます。置き場やページが一時的に使えない間は置けず、使えるようになった回に置きます。見回りは締切を過ぎた時点を置きません（同じ回にほかの時点を置くときも。書き出しの途中で締切を過ぎたときも、正式な名前に置く直前に時計を見直して置きません）。正式な名前に置く直前には、最新の発走時刻と保存したページも確かめ直し、発走時刻（締切）やその時点のページが変わっていれば、新しい状態で作り直してから置きます（別の見回りが途中で発走時刻を変えても、古い締切の入力は置きません。置いた後に発走時刻が変わっても、置いた入力は入れ替えません。受付は今の締切で判定します）。手で動かす `keiba mam export` は締切を問わず、まだ無い入力を置きます（手で復旧するため。締切後に作った予想は受け付けません。そのときあるページで置き、発走時刻が変わっていれば作り直します）。正式な名前に置いた後に止まったときは、置いた入力がそのまま正式です。置き場が「ハードリンク」も「上書きしない移動」も使えないときは、入力を置きません（見回りが毎回知らせます）。

```json
{
  "schema": "keiba-mam-input-v1",
  "race_key": "2026-11-22|京都|11",
  "time_point": "1h",
  "deadline": "2026-11-22T14:40+09:00",
  "race": {"race_date": "2026-11-22", "venue": "京都", "race_number": 11, "post_time": "15:40",
           "surface": "芝", "distance_m": 1600, "field_size": 18, "race_name": "マイルチャンピオンS …"},
  "scratched_known": [7],
  "horses": [{"horse_number": 1, "waku": 1, "horse_name": "…", "sex": "牡", "age": 4, "weight_carried": 58.0,
              "jockey_name": "…", "trainer_name": "…", "sire": "…", "dam": "…", "damsire": "…",
              "past_runs": [{"date": "2026-10-17", "venue": "東京", "finish": 6, "dist": "1600芝", "time": "1:32.8", "f3": "35.2", "corners": ["4", "3"]}]}],
  "win_odds": {"1": 3.4, "2": 12.5},
  "trio_odds": {"1-2-3": 45.6},
  "odds_time": "14:25"
}
```
- `deadline`：この時点の締切。発走60分前（1h）や15分前（15m）です。予想は締切までに作ってください
- `scratched_known`：締切までに分かっていた取消・除外。`horses` には入っていません
- `win_odds`・`trio_odds`：締切までのオッズです。読み取りの合格判定に通らなかったときは `null` になります
- `trio_odds` に無い組は、その時点で「票数なし」（1票も入っていない）です。予想に入れてもかまいませんが、倍率が無いのでその組には配分しません
- 結果、締切後の情報、学習モデル・ルールの予想は入っていません

## 2. まむから返してほしいもの（予想）
1レース×1時点につき1つ。複数をまとめて配列にしてもかまいません。

```json
{
  "schema": "keiba-mam-prediction-v1",
  "race_key": "2026-11-22|京都|11",
  "time_point": "1h",
  "generated_at": "2026-11-22T14:35:00+09:00",
  "author": "mam",
  "ranking": [3, 1, 12, 5],
  "trios": [{"combo": "1-3-12", "p": 0.08}, {"combo": "1-3-5", "p": 0.05}],
  "confidence": "B",
  "comment": "一言（任意）"
}
```
- `generated_at`：予想を作った時刻です。**タイムゾーン付き**でお願いします。締切より後だと受け付けません
- `ranking`：強いと思う順の馬番です。全頭でなくてもかまいません
- `trios`：三連複の組と確率（任意）です。確率は合計1でなくてもよく、こちらで合計1に直します
  - `p` は0以上・100万以下の数です。文字列・非数・無限大・負の数や、全部0のものは受け付けません
  - 確率がある場合だけ、学習モデルと同じ決まりで仮想の配分をします（均等払戻・期待値・分数ケリー、1レース上限1万円、100円単位）
  - 確率が無い場合は、`ranking` から組の順位を作ります。確率の裏づけが無いので、配分は0円です
- `confidence`：A/B/C/D/Z（任意）。無ければ Z です
- 受け付けない例：締切後の作成、出走馬にない馬番・取消の馬、`ranking` の重複、`ranking` も `trios` も無い

## 3. 受け取った後
- 受け付けた予想は、学習モデル・ルールと同じ台帳に `text_ai` として記録します。書き換えはできません
- 統合（市場＋学習＋まむ）で正式な確率に使うのは、同じレース・時点で渡した入力（`horses`）の出走馬と、統合の時の出走馬が同じで、全組の確率がそろっているときだけです。取消などで出走馬が変わったときは、受け付けても統合は参考表示（配分しない）になります
- レース後に同じ決まりで精算し、月次の振り返り（`data/review/<月>.html`）に並べます
- 実購入はしません。初週は回収率の判定をしません

## 決めてほしいこと
1. **どの時点で出すか**：全部の時点か、1時間前だけか
2. **出し方**：ファイルを HEROINES に置くか、本人に渡すか
3. **確率を付けるか**：付ければ仮想の配分まで比べられます
