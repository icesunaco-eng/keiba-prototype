# 確認アプリ（PR #15）の受け入れ基準

**確定（2026-11-21 たかむね）**。のあがたたき台を作り、たかむねが「このままで」と決めた。

## なぜ作るか
- これまでの独立検証は「欠陥が1つでも見つかれば不合格」で、毎回新しい境目の反例が足されるため、終わりがなかった（7回で合格の観点 0→4）。
- 検証そのものは続けるが、**受け入れ（マージしてよいか）の線**を先に決める。

## 合格の条件
1. 指摘の重さを次の3つに分ける。
   - **止める**：お金の数字（実購入・仮想財布の払戻・返還・回収率）や保存した記録が誤る、または画面が使えなくなる。かつ、**ふつうの運用で起こりうる入力**で起きる。
   - **直してから**：ふつうの運用で起こりうるが、表示の誤り・説明の不足など、数字や記録は誤らないもの。
   - **あとで**：アプリ自身や収集が作らない壊れた入力（手で書き換えたファイル、ありえない値）でしか起きないもの、要件の外のもの、改善案。
2. 「止める」が **0件** なら合格。
3. 「直してから」は、件数と内容を報告に書き、のあが直したかを次の検証で確かめる（受け入れは止めない。ただし、たかむねが止めると決めたものは止める）。
4. 「あとで」は GitHub の Issue に残す（受け入れは止めない）。

## ふつうの運用で起こりうる入力（例）
- JRA のページの取得の失敗・途中まで（行の欠け、払戻がまだ載っていない、同着、取消・除外）
- 収集の原本ファイルが無い・空
- 予定表から外れた過去のレース（7日より前）
- 別のタブ・別の端末からの同時操作、古いフォームの送信
- Mac の再起動、自動起動の入れ直しの失敗
